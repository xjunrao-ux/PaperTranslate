# 字体、密集表格与导出命名

## 文章级统一样式

新任务 start 时只分析一次全文主字号、标题层级和字体类别，生成 style-profile.json。先展示简表，由用户确认一次，或记录其已指定的规范；后续按样式角色渲染，不再逐块猜字体。正文栏宽也一次确定并复用，短英文段落不再把中文栏宽限制成其最后一行的宽度。以下   是默认方案，可整体调整：

| 角色 | 中文字体 | 字号 | 行距／段后 |
| --- | --- | --- | --- |
| 正文 | 宋体类 | 原文主字号，全文固定 | 1.35 倍／0.6em |
| 标题 | 黑体类 | 全文主标题统一 | 1.2 倍／0.8em |
| 一级小标题 | 黑体类、加粗 | 正文约 1.18 倍 | 1.25 倍／0.55em |
| 二级小标题 | 黑体类、加粗 | 正文约 1.08 倍 | 1.25 倍／0.5em |
| 图注、表注 | 宋体类 | 正文约 0.9 倍 | 1.3 倍／0.45em |
| 脚注／页码 | 宋体／黑体类 | 正文约 0.75 倍 | 约 1.2 倍，无首缩；页码单行并沿用源锚点 |
| 作者／机构 | 署名保留原生字形，机构宋体类 | 正文约 0.9 倍 | 独立编号换行，不套小标题粗体 |
| 表格、图标签 | 宋体／黑体类 | 固定普通／紧凑档 | 以真实区域不碰撞为限 |

字号量化为 0.5 pt，具体值以方案表为准。例如正文 9 pt 时默认行距 12.15 pt、段后 5.4 pt。段后距与段内行距分开管理，不能用空行撑高。表格与标签不为了消除警报逐块调成不同字号，确实放不下时调整区域／行高或提交例外。

字体路径记录在方案 fonts 中，确认时记录文件哈希；更换字体或角色参数后需重新确认和构建。中文宋体类缺失时不能静默改成黑体后声称符合方案。字体不随包分发；可使用合法安装的宋体／思源宋体、黑体／思源黑体等。用户确认的统一方案优先于旧版逐块原字号策略。公式、代码、引用和保留的原标识不参与中文字体替换。后续文档若明确沿用同一规范，可 start --profile 指定已确认样式表，不重复询问。

黑体是类别，粗体是字重。源语义强调仍通过编号标记继承；整段标题由角色加粗。仿粗的描边统一随字号缩放，避免默认粗描边形成黑块。源字体元数据与实际不符时，使用带 reason 的 repair／高级 typography 修正，不对同名词全局加粗。

## 换行、段落对齐与留白

- 翻译前把 PDF 抽取出的视觉行还原为完整段落，修复可确认的跨行断词，再理解语义。不能把每个原文视觉行当作独立翻译单位。
- 中文由可用行宽重新换行；不逐字、逐行对应英文。不得在每句末尾强行回车，也不得为撑满栏宽插入空格。
- 中文句号、逗号、分号、冒号、问号、叹号和右括号等不得作为自动折行的行首；左括号和左引号不得孤悬行尾。尽量保持英文单词、数值与单位一体，过长且不能合理断开的标签应报告，不通过拆断单位来掩盖溢出。
- 保留真实段落、标题层级、列表项、公式和表格结构。标题与正文分开；列表项之间按原结构断行，不能连成一段。复杂提取错误需要先拆分块，不能凭空猜段落。
- 新任务段内行距采用已确认的角色样式（正文默认 1.35 倍），不逐段跟随来源基线；历史无样式表的任务才沿用来源基线间距。段间留白与段内行距分别处理。禁止靠往译文字符串填入多行空白实现对齐。

默认 build --alignment paired：保留双栏和跨栏结构，按每对段落实际高度取最大值；较短一侧段后增加高度差，再排下一段。英文 5 行、中文 8 行，同行距时英文段后约补 3 行高；行距不同则按实际测量补齐，不按数字行数机械相减。不在文本字符串中插入空行。两栏独立累计，跨栏标题／图表在两栏都完成后同步放置。

中文正文按源段落结构选择 2em 或顶格，段内行距 1.35 倍，段间适度留白；原文顶格、跨页续段及公式后解释不强制缩进。英文沿用原段距，不能把中文段后 0.6em 强加到英文上。页边版权条不进入正文流。页高按需要增加，不拉伸字形或图像。

严格原页与固定分页使用 position；明确自由单栏重排才用 paragraph。它们不能与 paired 混称为同一排版策略。paired 暂不自动把超长页拆成标准纸张续页，超过 PDF 页高限制时保持阻塞；图表内部标签放不下仍须处理真实边界。模式定义见 [页面契约](page-layout.md)。

## 密集表格／小图标签放不下时

5.1 pt 的原图标签不应被强制放大到 6 或 8 pt。提取器的文字 bbox 是字体包络，不一定是可写的单元格高度；辨认表格时同时检查文字基线是否位于单元格内。按单元格边界限制写入范围，使用随字号变化的小留白，不给 5.6 pt 的行固定扣掉 2 pt。

按下面顺序处理：

1. 查看源页与任务：检查是否把整行／多格合成一个块、是否漏识别了单元格、图标签框是否只是文字 bbox。必要时拆分块或校正节点边界。
2. 核对所选普通／紧凑档是否适合真实边界；新任务全篇使用确认后的档位，不为个别单元改字号。先实际测量，再判断是否溢出。不能仅用“6×1.25 大于行高”宣判所有中文放不下。
3. 使用单元格／节点内的真实空白优化换行、居中和留白，保留全部含义、专名及数字；图线和邻格不能被覆盖。
4. 原位仍无法容纳时提出具体选项：局部增加行高、调整列宽、整表重排，或提供独立的完整译表。这些会影响原版式，需向用户说明。移动括号英文到表下注释须先取得用户同意。
5. 只有截图时解释原因和可选方案，不声称已修复该篇文献；需有原 PDF 和任务／报告才能逐格验证。

`overflow` 报告给出块 ID、页码、可用宽高、来源字号、最低字号及实际字体。因为字号／空间问题设置的 `keep` 会被标记为未完成，不能把几十个未翻译表格单元归为“合理保留”。草稿中暂时保留原区域用于防止破坏，但必须统计未完成区域并保留完整译文。

## 统一文件名与导出

`output/translated.pdf`、`bilingual.pdf`、`report.md`、`qa.json` 是任务内部工作文件名。面向用户的交付必须通过 `export`，不再由各 agent 临时起名。

完成全部核验后：

```text
python <tool> export <job> --directory <deliverables> --revision 1
```

以源文件 `My Paper.pdf` 为例：

| 成品 | 文件名 |
| --- | --- |
| 中文译文 | `My_Paper__zh-CN__r01.pdf` |
| 左英右中对照 | `My_Paper__en-zh-CN__r01.pdf` |
| 翻译疑问与审阅报告 | `My_Paper__review__r01.md` |
| 机器核验记录 | `My_Paper__qa__r01.json` |
| 交付清单与 SHA-256 | `My_Paper__manifest__r01.json` |
| 图片任务的逐页译图 | `My_Paper__zh-CN__p0001__r01.png` |

规则：保留源文件主名，Unicode 采用 NFC，空白改下划线，Windows 非法字符改下划线，处理保留设备名，主名最多 100 个字符。`--name` 可明确指定主名。固定使用语言代码和 `rNN` 修订号，不使用含糊的“最终版”“最终修改版”。

未核验／有未完成区域时只能显式用 `--draft` 导出，所有文件强制添加草稿标识，例如 `My_Paper__zh-CN__draft__r01.pdf`。任务或输出变化后拒绝导出旧结果。同名不同内容拒绝覆盖，改用 `--revision 2` 得到 `r02`；相同内容重复导出保持幂等。

额外生成的译注 PDF 沿用 `主名__review__rNN.pdf`，附件独立交付用 `主名__attachment-001__附件主名__zh-CN__rNN.pdf`。这些可选文件不是当前 `export` 自动生成的内容；若额外交付，应同步增加清单记录，不能伪称脚本已生成。
