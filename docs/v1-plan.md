# PDF 翻译 Skill：v1 需求与疑问解答

规划记录日期：2026-10-02。本文保留当时已确认需求与实现建议。

实现更新（2026-11-07）：v1 已完成基于 PyMuPDF 的本地块处理与排版流程，翻译由调用 skill 的当前会话提供；本版不接入 BabelDOC 内部接口。当前实现、验证范围和限制见 [v1 实现记录](implementation-v1.md)，入口见 [SKILL.md](../skills/pdf-translate/SKILL.md)。下文候选引擎与待验证事项属于原规划，不代表全部已实现。

## 已确认需求

| 项目 | 要求 |
| --- | --- |
| v1 语言 | 英语原文翻译为中文；其他语言留待后续版本 |
| 输入 | PDF 文献及其他待翻译 PDF |
| 输出 | 译文 PDF，以及英文在左、中文在右的双语 PDF |
| 版式 | 尽量保留原页面、分栏、标题、图表、公式与编号 |
| 对齐 | 对应内容块对齐，包括标题、正文段落、列表项、图注和表注等 |
| 专名 | 专有名词、人名等译名后，以括号附上原英文 |
| 疑难处理 | 对识别不清、译法歧义及原文疑点提出问题，提供依据和候选方案，辅助用户裁决 |
| 图片文字 | 尽可能翻译；根据文字存储方式及识别、排版能力处理，记录未完成区域 |

## 内容块对齐的具体含义

每个原文内容块与一个译文内容块或一组译文片段建立稳定对应关系。双语 PDF 左右两侧对应块的起始位置对齐；块内根据语言各自断行，允许行数和文字高度不同。

内容块包括标题、正文段落、列表项、图注、表注等。公式和图表作为受保护内容保留，其周围的说明文字按对应块处理。表格中的文本需要保留行列和单元格对应关系，不能拆成无关联的段落。

仅将整张原文页与整张译文页并排，不足以证明内容块已经对齐。需要保存页码、块编号、坐标及跨页关联，并检查对应块的实际位置。

跨栏、跨页段落可以在翻译时结合完整上下文；排版时保留原页片段之间的关联，分别回填。不能因合并段落而改变左右对应关系。

原文侧优先直接保留原 PDF 页面；译文侧按原内容块的区域和起始位置排版。实际坐标误差容限、最小字号等参数需要用样本验证，尚未定值。

译文溢出的建议处理顺序：

1. 在内容块内调整断行、间距。
2. 在经验证的字号下限内调整字体大小。
3. 检查可用空白，不遮挡下一内容块或图表。
4. 如果仍不能容纳，记录受影响页和块，提出带续页、扩展区域或局部重排的方案。任何降级都需保持内容关联，并在报告中说明其对原版式和对齐的影响。

完整内容、阅读清晰、对应关系、原版式之间可能存在冲突。不能以删句、截断、摘要替代完整翻译，也不能用极小字号隐藏排版失败。无法对齐的块应标记为待处理，不能将其视为验收通过。

## 专有名词、人名的括号英文规则

已确认的输出形式是“中文译名（原英文）”。例如：

- 艾萨克·牛顿（Isaac Newton）。
- 随机森林（random forest）。
- 马萨诸塞理工学院（Massachusetts Institute of Technology）。

以下是实现建议，尚未作为用户另行确认的细则：

1. 对被识别为需要保留原名的专名、人名及关键术语，默认每次出现都附原英文。可以提供“仅首次出现”选项，但不能在排版拥挤时自动切换该规则。
2. 采用用户指定或已有可靠依据的中文名称。没有可靠译名时保留英文，并将需要裁决的名称列入报告；不能仅凭模型猜测认定权威译名。
3. “原英文”保留原文中的名称信息；可以修复 PDF 排版造成的断字或连字符换行，但不能擅自添加原文没有出现的全称或缩写。
4. 同一实体出现全称、简称或不同拼写时，术语表记录这些形式与统一译名的关联，避免重复括号和前后不一致。
5. 正文中的人名采用上述规则；文献条目中的作者名、DOI、网址、标识符及代码优先保留原样。参考文献标题是否增加译文可后续配置。
6. 所有新增英文括号都参与实际排版和溢出检查，不能先按纯中文排版再直接追加。

术语表至少保存原文名称、中文译名、类别、英文保留规则、首次出现位置及裁决状态。歧义不能仅通过简单的全文字符串替换解决，需要结合具体上下文。

## “调用原有功能”是什么意思

这里指把现有开源工具作为本项目的依赖：由项目脚本调用它们已实现的 PDF 解析、翻译流程和排版输出能力，再加入本项目自己的规则与校验。

它可以表现为两种方式：

- 命令行调用：脚本运行已安装工具，传入文件、语言、术语表和输出目录等配置，再读取结果。
- 程序接口调用：项目代码通过工具提供的接口接入流程，按接口能力取得进度、译文或中间数据。

这不意味着已有工具自动满足全部需求。具体职责建议如下：

| 模块 | 复用候选 | 本项目需要实现或验证的部分 |
| --- | --- | --- |
| PDF 翻译与基础排版 | PDFMathTranslate-next 及其 BabelDOC 后端 | 原页保护、输出流程和实际保版式效果 |
| 术语约束 | 已有术语表与提示配置 | 名称识别、中文加括号英文、用法一致性及检查 |
| 双语 PDF | 已有并排输出能力 | 左英文右中文，以及内容块起始位置对齐的实际校验与必要修正 |
| 疑难审阅 | 翻译模型及结构化内容 | 问题清单、依据、候选译法、用户裁决保存和回写 |
| 图片文字 | 文本对象提取，后续 OCR | 分类、识别核对、局部翻译及科学数据保护 |
| 交付检查 | PDF 提取和渲染工具 | 覆盖清单、溢出检查、数值公式保护、页面视觉核验 |

建议的流程：输入 PDF → 提取内容块及术语 → 翻译并记录疑难 → 应用裁决 → 排版 → 双语输出 → 内容及视觉检查。

翻译引擎负责处理 PDF 的流程；语言模型或翻译服务负责生成译文；skill 负责指导何时调用脚本、采用什么规则以及如何向用户交付。使用现有工具并不等于必须使用它的在线网站，处理位置取决于实际配置。即使 PDF 在本地处理，使用远端翻译接口时仍会向该服务发送相应内容，需要在运行说明中明确。

尚未选择翻译服务、模型、接口配置和费用方案；本次只记录需求，不安装依赖或发送文档。

## 官方资料核查及对上一版方案的修正

截至本次查阅：

- [PDFMathTranslate-next](https://github.com/PDFMathTranslate/PDFMathTranslate-next) 的官方说明显示其基于 BabelDOC，并提供保留排版的论文翻译和双语比较能力。
- [BabelDOC](https://github.com/funstory-ai/BabelDOC) 的官方说明提供英译中设置、并排双语输出、术语表和自定义翻译提示配置；表格文字翻译标为实验功能。
- BabelDOC 的 Python API 部分将其接口标为内部接口，官方建议通过 PDFMathTranslate-next 的高层调用入口接入。因此，上一轮提到“直接用 BabelDOC Python API”需要修正：优先验证官方推荐入口，并固定依赖版本，不能假设内部接口长期稳定。

工具有术语表和提示配置，不等于已保证专名括号规则；工具有并排输出，也不等于已保证内容块对齐。这两项均需要独立验证。

## v1 基本功能的建议边界

v1 先以有可用文本层的英文 PDF 为验收对象，包括普通单栏和双栏文献。先跑通：

1. 正文、标题、图注、表注的英译中。
2. 专有名词、人名的中文加括号英文规则及术语记录。
3. 原格式译文 PDF 和左英文右中文的双语 PDF。
4. 内容块对应、起始位置对齐、溢出和缺失检查。
5. 疑难问题报告、用户裁决保存与受影响内容的重新生成。

可直接提取的图中文字纳入基本翻译流程。复杂表格、扫描件以及嵌入位图的文字先做检测与记录，逐步加入 OCR 和局部替换；无法处理时保留原图并给出对应文字说明或未完成清单，不将其宣称为已完成翻译。此处是为实现基本功能提出的分阶段建议。

其他源语言、复杂扫描件处理、逐行对齐和任意背景上的图片文字替换留待后续版本验证。

## 第一轮技术验证与验收

优先选择具有段落、图注、公式及专名的少量英文 PDF 页面，验证：

- 能否取得内容块的原文、位置及稳定关联。
- 能否将译文和用户裁决回写到排版流程，而不是只能取得最终 PDF。
- 增加英文括号后能否保持块对齐且不出现遮挡、裁切或不可读字号。
- 能否保护原文侧、公式、数值、单位、图表及引用编号。
- 能否记录全部输入块的处理状态；未翻译或未裁决的内容是否在报告中可定位。
- 同一人名或术语是否前后一致，局部修改是否能更新相关输出。

通过这些验证后再确定接入方式和参数。若原有接口无法支持译文回写或块对齐，应扩展适配层或替换相关模块，而不是降低用户确认的要求。
