# v1 实现与验证记录

日期：2026-11-07。

## 已实现

- 可发现的 `pdf-translate` 技能入口与 UI 元数据。
- 独立 CLI：doctor、prepare、glossary、import、decide、figure、render、preview、verify。
- 英文文本层 PDF 的源页副本、内容块提取、双栏排序启发式、相邻行合并和基础有边框表格单元格识别。
- 通过助手会话生成并导入译文，无额外翻译服务或密钥。固定依赖 PyMuPDF 1.26.7，嵌入 CJK 字体。
- 专名占位符、确定性中文加括号英文、每次/首次出现模式、词边界及最长名称优先匹配。
- 译文输入哈希、增量导入、术语变化后失效检查与断点续跑。
- 重大/次要疑难项、候选译法和裁决记录；问题变化后旧裁决失效。
- 先测量后写入，保留图片和矢量线条，字号下限、缺字检查、数字核对与溢出草稿。
- 同尺寸译文 PDF 和左英文右中文的宽页 PDF；内容块起始坐标保留。
- 位图区域截图、人工检查和报告中的图中文字补充翻译。
- 完整审阅报告、未排译文、自动检查与视觉核验状态。
- 可复制的个人技能安装脚本及 ZIP 打包脚本，不覆盖不同的已有安装文件。

## 接入方案

复用 PDF 库的提取、文字层移除、字体嵌入、页面合成和渲染能力。专名、疑难裁决、块对齐和交付协议由本项目实现。

规划中的 BabelDOC/PDFMathTranslate-next 保留为未来候选适配器，本版不依赖其内部 API。选择直接控制坐标的流程，是为了先验证译文回写、专名括号和块起点对齐，而不是只取得最终翻译文件。

## 自动化测试

执行：`.venv/Scripts/python.exe -m unittest discover -s tests -v`。

测试覆盖：

1. 译文专名括号、原文侧像素一致与矢量线条保留。
2. 丢失/重复术语占位符时原子拒绝导入。
3. 数字变化进入草稿，不能标记完成。
4. 译文溢出保留原区域，并在报告完整保留译文。
5. 重大疑难需裁决，问题变化后旧裁决失效。
6. 术语表更新使旧译文和输出失效。
7. 位图未核对时阻塞，图片说明修改使旧输出失效。
8. 相同任务续跑保留译文。
9. 未导入的内容块不能被计为完成。
10. 独立公式按原样保留，像素不变。
11. 扫描/无文本页被标记为待处理。
12. 首次出现附原文模式。
13. 中文闭合标点不单独放到下一行开头。
14. 简单表格使用单元格空间，保留表格线与数值。

## 实际 PDF 样本

`examples/build_demo.py` 生成两页合成文献，涵盖双栏、两个人名、方法名、表格、独立公式和带英文标签的位图。该脚本使用已知译文验证流程，不替代真实文献翻译质量评估。

示例任务：`output/demo/job-v1-layout`，15 个内容块，其中 13 块翻译、2 块数值/公式保留，1 个位图区域提供补充译文。

自动 verify 回提取译文，检查块起点误差不超过 0.75 pt，并比较两页双语左侧与源页的 72 DPI 像素。另查看译文与双语页面 PNG，核对字号、断行、表格、公式和图像。

## 明确未完成的能力

- 扫描件自动 OCR 与完整扫描页翻译。
- 位图内部英文的原位抹除与重写；目前只在报告给出翻译。
- 混合数学段落、任意复杂表格、复杂阅读顺序的通用重建。
- 全部字体样式、交互注释、表单、签名及链接的完整保真。
- 除英语到简体中文之外的语言组合。

自动核验不证明语义或术语识别完整；真实文献仍需上下文、专业术语和图片的审阅。超出能力的区域明确留待处理，不能计入完成。
