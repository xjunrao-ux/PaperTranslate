# v2.2 实现与验证

本版解决 DSH 示例中强调位置错误、正文误判公式、图例保留漏验、最终 PDF 与 qa／报告脱节的问题，并将主要排版参数收敛为文章级样式表。没有改写用户提供的 VPR-Evolve 原任务或伪称其已修复完成。

## 全文统一规则

start 一次识别主字号与角色，生成 style-profile.json。向用户展示简表并确认后锁定；用户已明确指定的规范可以直接记录，沿用已确认方案可用 --profile。确认记录包含实际依据、字体路径及文件 SHA-256。不能伪造用户确认。

正文宋体类、标题与小标题黑体类；图注与表注使用固定档位。正文默认 1.35 倍行距、0.6em 段后距，正文栏宽统一。渲染只读取已确认方案，不重复猜每段字体。保留语义粗斜体，但不将黑体类别等同于粗体字重。表格采用固定普通／紧凑档，溢出仍需调整区域或布局，不逐格缩字。

## 精简与可移植性

正常工作流为准备确认、批量翻译、核验交付三个阶段。next／apply 只交换待译文本与出现位置专属的样式标记；批次哈希与 Unicode 偏移由脚本处理。数字、原生公式、参考文献等由程序分类保留，代码区域合并为一份中文注释任务。模型不需要读取完整页面 JSON、重复上下文或全部参考文档。

build 不先导出一套原坐标中间 PDF；默认只生成双语预览，无变化复用已有结果。finish 重新检查实际输出，重建报告并规范导出；修正进入同一任务，禁止依靠未入账的补排 PDF 或追加说明冒充完成。

通用包和 WorkBuddy 元数据包共享全部核心脚本，不依赖特定模型 API。可安装格式经过检查，但 DSH／WorkBuddy 宿主内的真实端到端执行尚未验证。字体不随包分发，跨机器保持一致需要同一合法字体文件。

## 验证范围

- 自动测试 50 项，覆盖旧协议和新协议：样式确认、统一字号／字体／间距、编号强调标记、原生分式上下标与横线、保留图例被破坏时拒绝验收、过期批次、跟踪修正、缓存、最终输出复验及命名导出。
- 两页自造示例逐页查看双语预览：不同英文正文字体统一为同一中文样式；中文行距与段后距、密集表格、节点标签及两项图例均纳入检查。这不是对用户论文翻译质量的验证。
- 对 VPR-Evolve 七页原文只做隔离提取和任务量测量：398 个语义块，255 个模型待处理项（包括 1 个代码说明）；识别 99 个原生公式对象，其中 2 处边界仍须审阅，不能无条件自动放行。
- 原任务逐页 JSON 总计 858,167 字节；新待译条目数组 UTF-8 为 42,447 字节，减少约 95%。比较口径不含批次头、回复、图片及实际模型计费；不能据此声称 token 或费用减少 95%。

复杂背景、无可靠边界的公式、过高整图及无法容纳的单元格仍明确阻塞并保持草稿。自动检查不能代替语义和视觉审阅。旧任务保留原协议与译文，不隐式重新分段迁移。
